What changed in this session

  • New data layer in site_data/: star roster, restaurant detail, hotels, activities, social accounts, and the framework (plan, budget, itineraries, flags, questions, suggestions).
  • New generator build_site.py, standard library only, which refuses to publish a page with a dangling link, a duplicated id, or an unescaped template token.
  • New site of 11 pages in docs/, regenerated from the data, with a card layout below 700px so no table needs horizontal scrolling on a phone.
  • Superseded pages removed so no two pages in the published tree describe the same thing differently.

How to check this work

  1. Re-run the build: python3 build_site.py. It prints every check it ran. A failure exits non-zero.
  2. Spot-check a row: open the source link in the row and compare the number. Hotel URLs carry the dates in the query string, so the price reproduces.
  3. Check a blank: every blank on the site should appear on the Flagged page. A blank that is not flagged is a defect.
  4. Check a derived number: the formula is on the Method page and the inputs are in site_data/*.json.

What is still missing from the repository itself

  • No licence. Decide before sharing the repo.
  • No CI. The build has checks; nothing runs them automatically (S-07).
  • No price history. Each build overwrites the last; a dated snapshot of site_data/ would show how prices moved (S-03).
  • No test for data shape. The generator fails on missing keys, but there is no schema that would catch a field quietly changing meaning.

Built 2026-11-25. Every figure on this site was read on an official page on that date unless the row says otherwise. Prices and hours change; re-check before booking. Rows that could not be verified are blank and listed on Flagged.
