Method &amp; sources

How every number on this site was produced, every source that was read, every source that failed, and the checks the build runs on itself.

Rules the site is built on

  1. Read it or leave it blank. A value appears only if it was read on the page linked in the same row. If it could not be read, the cell is blank and the reason is named.
  2. Never infer. No "typical" prices, no assumed opening hours, no guessed social handles.
  3. Separate the award from the listing. A star is an award; a venue in the guide carries a different badge.
  4. Label every derived number. Arithmetic on a verified figure is marked DERIVED and the formula is written down.
  5. Keep disagreements visible. When two official pages disagree, both numbers are shown.
  6. Date every snapshot. Prices and hours were read on 2026-11-25 and will drift.

The travel model, stated plainly

Travel minutes shown anywhere on this site are modelled: straight-line distance from the hotel's coordinates divided by an assumed average speed, with a fixed allowance for platform access and waiting. They are not schedules.

Why it matters: the brief's central constraint is "an hour or less". A straight-line model understates real trips that require a transfer, and it cannot see the East River. A few legs were checked against a real transit router and were consistent with the model, but no full matrix was measured. Treat every "within the hour" statement as provisional (F-05, Q-19, S-02).

Build checks

The generator refuses to publish if any of these fail:

  • Every internal link (nav, body, footer) resolves to a file that exists.
  • No unrendered template tokens or HTML-escaped markup leaks into the output.
  • No placeholder links that point at nothing (a bare hash).
  • No duplicate element IDs; every table row has the same number of cells as its header.
  • Every data row in the restaurant, hotel and activity tables carries at least one outbound source link.

These checks are run by build_site.py on every build and their result is printed to the console.

Known structural limitation: two datasets

An earlier session published a second, independently researched dataset alongside this one, still live at the deep dive. It disagrees with this site on the star count (69 vs 72), the hotel shortlist, the transit method and the hotel ranking basis. This site does not merge the two, because merging would silently choose a winner.

This dashboard is the canonical one for the reasons on the repository review: it carries per-row hours, prices and social accounts that the deep dive does not, and it states its own verification counts instead of implying completeness. The deep dive is kept only so the earlier work is not lost (suggestion S-01, question Q-23).
